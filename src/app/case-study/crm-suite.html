Case Study · CRM SaaS Suite

Rebuilding a four-app CRM suite,
with a team of seven.

The old platform was slow, fragile, and out of road. I researched and rebuilt the whole suite with the team already running it.

Tandemloop · 2023 to 2025 · Team of 7
Angular 17 GraphQL PrimeNG Firebase Flutter MEAN stack
Where it started

A legacy suite that had run out of road

The product was a set of CRM apps built years earlier. By the time I picked it up it was slow, bulky, and running on old tech. Bugs were hard to fix, new features were harder to add, and it carried real security vulnerabilities.

The decision was made to rebuild it from scratch rather than keep patching it. I was assigned to research the new suite and get it built with the existing team, who were already comfortable in the MEAN stack.

Before handing it over

I set the base up first, then split the work

Before pulling the team in, I listed every issue the old project had and set up the base of the new one. Getting the foundation right up front meant the team could build on something solid instead of arguing about structure halfway through.

Then I made each person responsible for one module and asked them to research it properly before building anything. Seven people across frontend, backend, QA, and UI/UX, each owning a piece of the suite.

Handing each person a module they owned end to end kept the work clear and the accountability obvious. Nobody was waiting on me for direction on their own area, and I could focus on the parts that cut across everything.

The decisions

The calls that shaped the rebuild

Four decisions set the direction for everything that came after.

01

Angular 11 → 17

The old app was stuck on Angular 11. I moved the rebuild to Angular 17 for modern patterns, better performance, and a version we could actually maintain.

02

REST → GraphQL

There were 200+ APIs. Maintaining and scaling that many REST endpoints was hard. We moved to GraphQL because the flexibility of querying exactly what each screen needed was our priority at the time.

03

PrimeNG as the design system

Picked PrimeNG for streamlined theming and a consistent component set across all four apps, so the suite felt like one product instead of four.

04

Firebase JWT auth

We were also building the mobile app in Flutter. To keep authentication common across web and mobile, I went with JWT-based auth on Firebase, so both sat behind one identity.

What I owned

Research, standards, and keeping it on track

I handled the parts that set the direction: the initial R&D, the base setup, and finalizing the tech and systems. From there it was about keeping quality up across seven people.

  • Ran the initial R&D and finalized the stack and architecture
  • Built the base setup before handing modules to the team
  • Set the coding standards everyone worked to
  • Reviewed the team's code
  • Kept a proper test flow in place
  • Monitored the deployments
Where it landed

A suite that was actually built to last

The rebuild shipped as a more stable, more robust platform with a clean UI. We came out of it with a structure that was genuinely easy to scale, and the day-to-day numbers moved in the right direction.
