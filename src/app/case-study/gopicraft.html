Case Study · Home Server Build

I stopped paying for cloud storage.
Built my own instead.

One old HP laptop, one bored weekend, and a storage problem I was tired of dealing with. Here is how gopicraft.dev came to life.

Chennai, India · One weekend build · Only cost: a domain name
Ubuntu Server CasaOS Immich Jellyfin Cloudflare Tunnel gopicraft.dev Docker
Why this happened

I have been collecting memories for years

Photos since childhood. Family trips. School friends. College. Office. Everything. Then videos too. Movies, series, anime. A lot of it. At some point it got big enough that I bought an external SSD with a connector just to store everything in one place.

That worked for a while. But it had real problems. If I wanted to back up photos from my phone I had to physically connect the drive. If I wanted to share an album with family I had to send files on WhatsApp or upload to Google Drive. If I wanted to watch something I had to carry the SSD around. Not convenient at all.

I was paying for Google Photos to back up my phone and share albums. But it always felt wrong to hand over personal photos and memories to someone else's server. And every year they find a new reason to reduce free storage or change the pricing.

So one weekend I had nothing useful going on and I thought about this properly. I already had an old HP laptop sitting unused. Decent specs. 12th gen i3, 16GB RAM, 250GB SSD, 1TB HDD. Just collecting dust in the corner. What if I just turned it into a server?

That weekend I decided to do exactly that. Full private cloud. Photos, videos, remote access. On hardware I already owned. No new purchases, no monthly subscriptions.

Before you start

What you actually need for this

The requirements are simpler than most people expect.

Requirements

  • 01
    An old laptop or desktop. Mine had 16GB RAM but 8GB works fine for basic setups. Any machine that can run Linux is enough.
  • 02
    WiFi at home. Ethernet is more stable but WiFi works. The server connects to your home network and that is it.
  • 03
    A USB drive, at least 8GB, to install Ubuntu Server from.
  • 04
    A domain name. // optional but worth it Without it everything still works on your home network. With it you get a proper URL accessible from anywhere.

That is the full list. No server rack. No special hardware. The laptop I used was an HP DA0077TX that had been sitting unused for months. The whole build cost me exactly the price of a domain name.

Step 01

Wiping the laptop and installing Ubuntu Server

The laptop had some old stuff on it that I did not care about. Formatted it completely. Clean slate before anything else.

For the OS I went with Ubuntu Server 22.04 LTS. No desktop, no GUI, just a lean terminal-based server. It is the standard choice for home servers for a reason. Stable, well documented, huge community.

The installation process looks like this. I used Balena Etcher to flash the Ubuntu Server ISO onto a USB drive. It is free, straightforward, and works on Windows and Mac.

01

Download Ubuntu Server ISO

Go to ubuntu.com/download/server and grab the latest 22.04 LTS ISO. About 1.5GB.

02

Flash it to USB with Balena Etcher

Download Balena Etcher from balena.io/etcher. Select the ISO, select your USB drive, click Flash. Takes about 5 minutes.

03

Boot from USB on the laptop

Plug the USB into the server laptop. Boot and press F9 on HP to get the boot menu. Select the USB drive.

04

Follow the Ubuntu installer

Set your language, storage layout, username and password. I set my username as rookie since it is a home server and the name felt right. The whole install takes about 15 minutes.

05

Install CasaOS

Once Ubuntu is up, SSH in and run the one-line CasaOS installer. It sets up a clean web dashboard for managing everything.

rookie@rookie: ~
# SSH into your server from another machine on the same WiFi
ssh rookie@192.168.1.37
# Install CasaOS with one command
curl -fsSL https://get.casaos.io | sudo bash
CasaOS is running at http://192.168.1.37
# Open that IP in your browser — you have a server dashboard now

After this, open a browser on any device connected to the same WiFi and go to your server's IP. You get the CasaOS dashboard. That is your server's home from here on.

On the username: I set mine as rookie during the Ubuntu install. It is just a label for the server. Pick whatever makes sense to you. It shows up in your terminal prompt as rookie@rookie:~$ which is just username@hostname.

Step 02

Picking a domain name

I wanted one domain for everything. Not just the server. Portfolio, side projects, apps, home server. One name that grows with me.

My name is Gopinath. Most popular extensions with that name are already taken. So I had to think. Looked at gopi.sh, gopilabs.dev, gopiforge.dev. All decent. I landed on gopicraft.dev.

Craft felt right. I build things and I care about how they are made. Not just shipping something and moving on, actually crafting it properly. The .dev extension enforces HTTPS by default which is a nice technical bonus for a developer's domain.

Registered it on Cloudflare Registrar for $12.20 a year. Around 1020 rupees. No first year discount tricks, no renewal price hikes. Cloudflare charges at cost. Since I was going to use their tunnel and DNS anyway, this was the obvious choice.

// gopicraft.dev — $12.20/yr, renews at same price, HTTPS enforced on .dev
Step 03

Giving the server a fixed address on the network

By default routers assign IPs to devices dynamically. Every time the router restarts it can give your server a different IP. That breaks SSH configs, tunnel setups, everything that references the server by address.

The fix is reserving a specific IP for the server's MAC address in the router settings. From that point on the server always gets the same address no matter how many times the router restarts. I set mine to 192.168.1.37.

// Syrotech router that comes with Railwire fiber — reserved a fixed IP for the server
Step 04

Getting storage right before anything else

My laptop has two drives. A 250GB SSD and a 1TB HDD. By default CasaOS was writing everything to the SSD. Photos, databases, all of it. That needed to change.

SSD is fast but limited. It is for the OS and Docker only. The HDD is where all the actual data goes. I set that rule early and stuck to it.

SSD — 250GB

250GB
  • Ubuntu Server
  • Docker engine
  • Container images
  • App configs

HDD — /storage

1TB
  • appdata/immich/pgdata
  • media/library (photos+videos)
  • media/movies
  • backups
// lsblk — SSD on sdb2 at /, HDD on sda2 at /storage
// HDD in fstab with UUID — mounts automatically on every boot

The actual work here was finding the docker-compose files CasaOS uses for each app and redirecting all the volume paths from /DATA on the SSD to /storage on the HDD. This is where I hit the most trouble.

Postgres kept getting stuck in "health: starting" for almost an hour. Eventually figured out the container runs as user 999 internally, not 1000 like most others. Had to set the right ownership on the data folder. Then hit a version mismatch between the Immich server and the postgres image that needed a full reinstall. Spent a lot of time on this with Claude's help going through it step by step.

// Both volume sources now pointing to /storage on the HDD
// 307MB postgres + 15MB media both confirmed on HDD

Postgres inside Docker runs as user 999. Not 1000. If you chown 1000:1000 the pgdata folder, it silently fails its healthcheck. You need chown 999:999 for that specific folder. Took me longer than I would like to admit to figure this out.

Step 05

Immich — finally done with Google Photos

Immich is the best self-hosted photo library right now. Proper mobile app, auto-backup, face detection, shared albums, timeline view. Everything Google Photos has but on your own hardware.

Installed it from the CasaOS app store. After sorting out all the storage issues it came up cleanly on v2.6.3.

// Immich v2.6.3 — server, postgres, redis all healthy and running

Installed the Immich app on my iPhone, pointed it to photos.gopicraft.dev, turned on auto-backup. Every photo I take now syncs automatically to my own server. Deleted Google Photos off my phone the same day.

Sharing works exactly how I wanted. Create an album, add photos and videos, generate a share link, send it on WhatsApp. The other person just opens it in their browser. No app to download, no account needed, no Google login. Just a link.

// CasaOS file manager picked up my external SSD automatically — can browse and copy from the browser itself
Step 06

Jellyfin for movies, series and anime

All those movies and series sitting on the external SSD, barely accessible. Now they live on the 1TB HDD and stream through Jellyfin.

Jellyfin is a free open source media server. It reads your files, pulls in metadata, posters, subtitles, everything automatically. You get a proper streaming UI that works from any browser or the Jellyfin app. Think of it as a self-hosted Netflix for your own collection.

Installed it from the CasaOS app store. Pointed it to the movies and TV folders on /storage. It scanned everything and built the library on its own. Now I can stream anything from my collection from any device, anywhere.

Jellyfin is completely free. No subscription, no license fees, no limits on users or streams. It is the honest answer to paying for multiple streaming platforms just to watch stuff you already have downloaded.

Step 07

Access from anywhere without opening a single port

My ISP is Railwire. Dynamic IP that changes every few days. Port forwarding would technically work but every IP change would break external access. Not a real solution.

Cloudflare Tunnel is the right answer here. The server reaches out to Cloudflare, not the other way around. No inbound ports to open, no firewall rules, no IP dependency. Just a persistent outbound connection to Cloudflare's edge that all traffic flows through.

Step 08

Locking the dashboard behind email verification

Immich has its own login so the photo library is reasonably protected. But the CasaOS dashboard gives full control over the server. Files, apps, Docker containers, everything. That needed a stronger gate.

Cloudflare Access is free with their Zero Trust plan. It intercepts any request to a URL and asks for email verification before letting anyone through. Only my email gets in. Everyone else is blocked before they even see a login page.

// Setting up Cloudflare Access
// Email OTP gate active on home.gopicraft.dev

Final security state: no open ports on the router, CasaOS behind Cloudflare email OTP, Immich behind a strong password, HTTPS enforced on the .dev domain, all traffic going through Cloudflare. For a home server this is more than solid.

Something I was skeptical about

Can a laptop actually run 24/7?

I was not sure about this. Keeping a laptop plugged in and running continuously felt like it would kill the hardware fast. So I researched it properly before committing.

Turns out most components handle 24/7 operation fine. CPUs, RAM, SSDs are all designed for continuous use. The HDD actually prefers staying spun up rather than frequent start and stop cycles. The real enemy is heat. Poor ventilation is what degrades things over time, not continuous operation itself.

The first component to go on an always-on laptop is the battery. Mine was already pretty degraded so that is not a concern. After that it is usually the cooling fan and eventually the power adapter. Both are cheap and easy to replace if they give out after a few years.

I placed the laptop on a hard surface with good airflow on all sides. Set up a temperature alert so if the CPU crosses a certain threshold it sends me an email. Temperatures have been completely normal under regular server load so far.

Still exploring wake-on-LAN over ethernet to wake it remotely if needed, and maybe a scheduled shutdown during late night when nothing is running. But honestly at around 100 rupees a month in electricity, the convenience of having it always on outweighs the cost.

If you are running a laptop as a server full time, consider removing the battery if it is easily removable. A battery always at 100% charge can swell over time and that can damage the motherboard. Running directly on the adapter is actually safer for this use case.

What this can become

A home server has a lot more potential

Photos and movies are just the start. Once the foundation is there, a lot of other things become possible without buying any new hardware.

  • Run a local AI model with Ollama. Install something like Llama or Mistral and you have your own private AI assistant that never sends your data anywhere. No usage limits, no subscription. On an i3 it is not fast, but it works for personal use.
  • Host personal projects and web apps directly. Each one gets a subdomain. gopi.gopicraft.dev, tools.gopicraft.dev, whatever you are building.
  • Self-host a password manager like Vaultwarden. Your passwords on your own server, not a company's cloud.
  • Add more storage by plugging in an external HDD. The setup scales without reinstalling anything.
  • Run a VPN server to secure your phone traffic on public WiFi.
  • Automated backups with rsync. Mirror everything on the HDD to an external drive on a schedule.

The one I am most interested in next is Ollama for running local AI models. The idea of having a private AI assistant with no data leaving the house, no API costs, no limits, running on old hardware that was just sitting there, is exactly the kind of thing that makes this whole setup worth building.

Honest takeaways

What I would tell someone starting this

Sort out storage before you install any apps. Decide where your data lives and set it up properly first. If you get this wrong everything you build on top of it is wrong too. I wish I had done this from day one instead of fixing it mid-setup.

Cloudflare Tunnel is the right answer for Indian home servers. Dynamic IPs from Railwire, Jio, Airtel, does not matter. Tunnel does not care about your IP. No port forwarding, free SSL, and the edge nodes are in India so latency is actually decent.

Container internals matter. Postgres runs as user 999 inside its container. Not 1000. That one detail caused the most debugging time in this entire project. Always check what user a container actually runs as before setting folder permissions.

An old laptop is genuinely enough. You do not need to buy anything new. If you have a laptop sitting around with 8GB or more of RAM, that is your server. The only purchase in this entire build was a domain name.
